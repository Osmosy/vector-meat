# 3D-симуляторы оборудования завода

Оборудование мясопереработки дорого учить «на живом»: остановка линии, риск травмы, порча
сырья. Интерактивный разбор узла в браузере снимает большую часть этого: оператор крутит один
регулятор и видит, что происходит внутри, механик проигрывает последовательность ТО, а
заказчику можно показать линию без выезда на площадку.

Скилл описывает, как строить такие страницы: что брать за исходные данные, как связать
движение и числа, где границы честности.

## Когда применять

- «покажи, как устроен клипсатор», «объясни оператору, что делает шнек»
- тренажёр последовательности разборки/сборки перед ТО
- разбор инцидента: где именно зажало, что не дошло до датчика
- показ линии инвестору, заказчику, новой смене

**Не применять:** схемы потоков и планировки (это 2D-диаграммы), расчёт режимов и рецептур
(это калькуляторы), цифровой двойник с реальной телеметрией (это интеграция с АСУ ТП, не
страница).

## Главное правило: один параметр

Вся сцена — функция одного числа. Не десять независимых анимаций, а одна:

    const pose = (u) => ({ ... })   // u: 0..1 или угол/оборот

Что берём за параметр у нашего оборудования:

| Оборудование | Управляющий параметр | Что считается из него |
|---|---|---|
| Клипсатор | ход штока 0..1 | положение пуансонов, раскрытие клипсы, усилие по кривой |
| Волчок | угол поворота шнека, ° | подача фарша за оборот, положение витков, нож |
| Куттер | угол чаши, ° | положение ножей относительно чаши, зазор |
| Термокамера | степень открытия заслонки 0..1 | расход воздуха, температура по датчикам, время цикла |
| Шприц вакуумный | ход поршня 0..1 | объём порции, положение цевки, синхронность клипсатора |
| Конвейер/транспортёр | положение ленты, м | сдвиг груза, работа фотодатчика |
| Обвалка/жиловка | угол ножа, ° | траектория реза, зона захвата |
| Запайщик/упаковщик | ход каретки 0..1 | смыкание губок, давление, цикл |

Из `u` считаются: положение деталей, показания приборов, графики, подписи, кадр видео. Если
что-то на экране живёт своей жизнью — рассинхронизация видна сразу, и правка расползается по
всему файлу.

## Исходные данные: только из документа

Правило апстрима, проверенное на их же примерах: **машины, придуманные из одного предложения,
выходят безликими всегда**. Порядок получения данных:

1. паспорт/руководство оборудования — габариты, ходы, диаметры, число зубьев, передаточные;
2. чертёж или схема кинематики — что с чем связано и через что;
3. фото/видео реального узла — пропорции, цвет, крепёж, направление вращения;
4. только потом геометрия в коде.

Реальные числа обязательны и проверяются арифметикой вручную, иначе симулятор врёт красиво:

    рейка 201 мм → шестерня 32 зуба, модуль 4 мм → делительный диаметр 128 мм
    половина длины делительной окружности = π·128/2 = 201,06 мм ≈ ход рейки (поворот 180°)

Если такой проверки нет — число в симуляторе ничем не подтверждено.

## Контракт кадра

    render(u)  — чистая функция: никаких Math.random, Date, накопленного состояния

Любой кадр восстанавливается из `u`, поэтому запись видео, живая страница и скриншоты для
инструкции не расходятся. Случайность — только на этапе сборки сцены, с фиксированным seed.
Всё, что «живёт само» (частицы, окалина, пар), считается один раз при загрузке в типизированные
массивы, а `render` их только читает.

## Что должно быть на странице

- машина в центре, панели по краям, ни одной цифры «для красоты»;
- кнопка «открыть узел»: разрез, изоляция, прозрачность, разнесение (explode);
- независимое управление подсистемами (привод / подача / узел работы);
- авто-тур, если страницу никто не трогает: 15–20 секунд, потом пауза;
- кадр 0 — уже машина, потому что он же превью ссылки.

## Шаблон в репозитории

`templates/simulator.html` — рабочий скелет страницы: клипсатор, один параметр (ход штока 0…40 мм
по паспорту), панели считаются из `pose(u)`, кнопки «разрез», «разнести», «авто». Открывается
двойным щелчком, сборка не нужна.

Что в нём настоящее: числа (ход 40 мм, раскрытие пуансонов 12 мм, кривая усилия до 2,4 кН),
связь «параметр → движение → подписи», структура панелей.
Что упрощено: сама геометрия — это скелет формы, а не обмер узла. Для тренажёра смены этого
мало: нужны размеры из паспорта конкретной машины, иначе получится «похожий ящик».

## Бюджеты

- страница < 1 МБ: мессенджеры и соцсети читают только HTML и сдаются на тяжёлом файле;
- 60 fps на встроенной графике, не на дискретной: тиры качества (без AO, ниже pixel ratio,
  меньшие карты теней, панели через кадр);
- прогрев шейдеров до первого кадра, иначе первый показ замирает;
- тяжёлые модели — отдельными файлами рядом, а не внутри страницы.

## Честность модели

Кинематика не равна физике. Показывая «усилие на пуансоне» или «давление в цилиндре», мы
показываем **модель**, а не расчёт: где взяли кривую, там и пишем, откуда. Для обучения
устройству этого достаточно; для прочности, гидравлики и выбора привода — считает инженер, не
браузер.

## Оборудование и безопасность

Симулятор показывает, но не заменяет: блокировки, аварийный стоп, порядок снятия давления
описываются словами рядом со сценой. Ни одна страница не должна выглядеть как разрешение
«сунуть руку, потому что модель открыта».

## Установка апстрима (если нужен их движок и три машины)

Навык `teardown` (MIT) умеет то же для станков: три готовые машины (V8, шасси Cessna 337,
Strandbeest), сборка офлайн-HTML, запись видео, процедурный звук.

    npx skills add elvarofficial/teardown -g -a claude-code
    cd <установленный каталог> && npm install && npx playwright install chromium

Требуется Node ≥ 20; для видео `ffmpeg`, для звука Python 3. Сборка страницы:
`node sims/build.mjs v8-live` → офлайн HTML ~800 КБ, 100–150 мс на страницу.

Грабли: на npm 11 (Node 24) `npm install` не выполняет postinstall esbuild, сборка падает —
лечится `npm rebuild esbuild`. То есть «одна команда» из описания — это четыре шага.

Движок (runtime, захват кадров, звук, правила ревью) взят у `whaleyxbt/claude-motion` (MIT);
в LICENSE стоят две строки copyright. Свои машины строим по тому же контракту, но со своими
размерами из паспортов.

## Встраивание в процессы завода

| Процесс | Как используется |
|---|---|
| Обучение смены | тренажёр: крутить параметр, находить узел, отвечать «что будет, если» |
| ТО и ремонт | страница = чек-лист разборки в правильном порядке, с разрезом |
| Разбор инцидента | изолируется узел, на котором остановилось, и показывается состояние |
| Приёмка оборудования | показ узлов поставщику и своей службе главного инженера |
| Продажи и экскурсии | линия без остановки производства и без допуска на площадку |

## Правила

- Один параметр на машину. Второй параметр — только если это отдельная подсистема с своим
  регулятором, и тогда он явно подписан.
- Каждое число на панели выводится из `pose(u)`, а не вписано в текст.
- Никаких «примерно таких» размеров: нет паспорта — симулятор строим как схему и пишем, что
  это схема.
- Страница работает без логинов и без запросов наружу. Наш шаблон берёт three.js через
  `importmap` с CDN (как принято в наших HTML); для офлайн-показа на площадке three вшивается
  внутрь — вес вырастает до ~800 КБ, как в апстриме.
- Русские подписи узлов — как в паспорте и в инструкции оператора, а не перевод «на глаз».

## Common Pitfalls

- **Придумать кинематику «по памяти».** Лечение: паспорт/чертёж/видео до первой строки кода.
- **Сделать десять независимых анимаций.** Лечение: одна функция `pose(u)`; всё остальное —
  её производные.
- **Числа в тексте рядом со сценой.** Лечение: только форматирование из `pose(u)`.
- **Назвать модель физическим движком.** Лечение: подпись «модель, кривая откуда взята».
- **Показать красивую страницу 15 МБ.** Лечение: бюджет 1 МБ и внешние файлы для тяжёлого.
- **Показать сцену без единого слова про блокировки.** Лечение: рядом с симулятором — правила
  безопасности и порядок снятия давления.
- **Первый кадр пустой.** Лечение: кадр 0 обязан показывать машину — он же превью.

## Verification Checklist

- [ ] Параметр один, назван и лежит в диапазоне
- [ ] У каждого размера есть источник (паспорт, чертёж, фото) и хотя бы одна ручная проверка
- [ ] Все числа на панелях считаются из `pose(u)`
- [ ] `render(u)` чистый: нет `Math.random`/`Date`/состояния между кадрами
- [ ] Узел открывается: разрез, изоляция, разнесение
- [ ] Страница < 1 МБ и работает офлайн
- [ ] Первый кадр показывает машину
- [ ] Рядом со сценой — блокировки и аварийный стоп
- [ ] Модельное отличается от измеренного и подписано

## Что не проверено

Собственных симуляторов оборудования завода в репозитории пока нет — скилл описывает метод,
взятый у `teardown`, и наш порядок работы с паспортами. Первый прогон на реальном узле
(клипсатор или волчок) добавит сюда числа и грабли, которых в апстриме нет.
