# План внедрения ИИ на мясоперерабатывающем заводе

Типовой завод. Переработка мяса без убоя. Адаптация матрицы ИИ-зрелости Д. Еремеева (krabster.ru).

## Специфика завода

- **Сырьё:** полутуши/отрубы (закупка, приёмка по качеству и весу)
- **Процессы:** обвалка → жиловка → посол/маринование → формовка → термообработка → охлаждение → фасовка → упаковка → маркировка → отгрузка
- **Вспомогательные:** мойка/санитария, холодильное оборудование, ТО, лаборатория
- **Регуляторика:** ФГИС Меркурий (эВСД), Честный Знак (маркировка), ХАССП
- **Потребители данных:** производство, ОТК, склад, снабжение, продажи, бухгалтерия

## Ключевые роли (адаптированные под завод)

| Роль в матрице | Аналог на заводе |
|---------------|-----------------|
| CEO / Собственник | Директор завода |
| CIO / IT-директор | IT-специалист / аутсорс-партнёр |
| CAIO (функция) | Куратор ИИ (новая роль или главный технолог с расширенным мандатом) |
| HRD | Начальник отдела кадров |
| CFO | Финансовый директор / главбух |
| Функц. менеджер | Главный технолог, начальник ОТК, начальник производства, начальник склада |

## Стадия 1: Сопротивление ИИ

### Компания в целом
ИИ отсутствует. Ветеринарные свидетельства (Меркурий) заполняются вручную. Маркировка (Честный Знак) — ручной ввод. Журналы ХАССП — бумажные. Производственные показатели — в Excel, часто на бумаге.

### Бизнес-модель
- **Что делает:** Работает по традиционной модели. Себестоимость считается постфактум в бухгалтерии. Нормы расхода сырья — из технолога «в голове». Прогноз продаж — интуиция коммерческого директора.
- **Что болит:** Непредсказуемый выход продукции (фактический % выхода vs плановый). Ошибки в Меркурии = остановка отгрузок. Просрочка сырья из-за отсутствия предупреждений. Штрафы за ошибки в Честном Знаке.
- **Что делать:** Провести аудит узких мест: где ручной труд делает критическую работу, где ошибки стоят денег. Посчитать потери от просрочек, ошибок маркировки, брака. Включить ИИ в повестку производственных совещаний.
- **Российская специфика:** Меркурий и Честный Знак — обязательны. Уже есть цифровой след в госсистемах. Это фундамент, от которого можно отталкиваться.

### Управление
- **Что делает:** Классическая линейно-функциональная структура. Нет ответственного за цифровизацию.
- **Что болит:** Каждый начальник цеха/отдела работает со своими цифрами. Сводка для директора собирается 3-5 дней после окончания месяца.
- **Что делать:** Назначить ответственного за мониторинг ИИ-возможностей (это может быть главный технолог или привлечённый специалист). Провести внутренний опрос: на каких участках люди тратят больше всего времени на рутину.

### Люди
- **Что делает:** Кадровый голод — стандартная ситуация. Обвальщики, жиловщики — дефицитные специальности.
- **Что болит:** Люди уходят туда, где платят на 5-10% больше. Сезонные колебания спроса создают пиковые нагрузки. Ветераны уходят на пенсию — знания теряются.
- **Что делать:** Зафиксировать знания технологов (нормативы, режимы обработки). Начать сбор данных о реальной производительности по участкам (сейчас это в головах мастеров).
- **Российская специфика:** Дефицит кадров в переработке — 15-20% по отрасли. Мигранты — нестабильный источник. Автоматизация и ИИ — не замена людям, а компенсация дефицита.

### Технологии
- **Что делает:** Стандартный набор: 1С (бухгалтерия/склад), Меркурий (один компьютер), Честный Знак (один терминал). Видеонаблюдение — есть, но без аналитики.
- **Что болит:** Данные разрозненны. Учётная система не знает, что происходит в цехе. Нет связи между закупкой сырья и выходом продукции.
- **Что делать:** Провести аудит данных: что оцифровано, что на бумаге, что в головах. Собрать требования к единой системе прослеживаемости: сырьё → продукт (сейчас это делается вручную в Меркурии).

## Стадия 2: ИИ как помощник

### Компания в целом
Первые шаги: установлены ИИ-инструменты для рутинных задач. Кто-то пробует ChatGPT для составления рецептур и расчёта норм. IT-специалист настроил автозаполнение Меркурия. Но это инициатива одиночек, не система.

### Бизнес-модель
- **Что делает:** Оцифрованы критические ручные операции. Автоматическое заполнение эВСД через API Меркурия. Автоматическая отправка данных в Честный Знак. Расчёт выхода продукции в Excel с формулами технолога.
- **Что болит:** Автоматизация на уровне «затыкания дыр». Отказал API Меркурия — всё встало, потому что резервного ручного процесса нет.
- **Что делать:** Провести пилот на одном переделе с измеримым результатом. Например: ИИ-расчёт норм закладки сырья по фактическому качеству партии (жирность, влажность) вместо табличных нормативов. Цель: рост выхода продукции на 1-2%.
- **Российская специфика:** API госсистем (Меркурий, Честный Знак) нестабильны. Нужен hybrid mode: автоматический + ручной с быстрым переключением.

### Управление
- **Что делает:** Директор дал поручение IT «внедрить ИИ». IT подписал завод на ChatGPT Team, показал технологам.
- **Что болит:** Нет владельца ИИ-процесса. IT отвечает за инструмент, но не может менять производственные процессы. Технологи говорят «нам это не надо».
- **Что делать:** Формализовать ИИ-функцию. Куратор ИИ = главный технолог + поддержка IT. KPI куратора: количество внедрённых ИИ-решений, снижение ручного труда на контрольных операциях.

### Люди
- **Что делает:** 2-3 человека используют ChatGPT для рабочих задач (рецептуры, письма, отчёты). Большинство в лучшем случае слышали, в худшем — считают угрозой.
- **Что болит:** Разрыв между «ранними последователями» и большинством. Обвальщики и фасовщики вообще не в контексте — им ИИ кажется чем-то из фантастики.
- **Что делать:** Прикладные воркшопы, а не массовое обучение. 1 цех × 1 задача: «Как мы считаем выход продукции сейчас и как может помогать ИИ». Важно: начинать не с ChatGPT, а с конкретной производственной задачи. Создать внутренний чат/канал обмена опытом.
- **Российская специфика:** Средний возраст на производстве 40-50 лет. Не «обучать ИИ», а «показать, как меньше переписывать бумажки». Формулировка критична.

### Технологии
- **Что делает:** Подписка на YandexGPT / DeepSeek / GigaChat. Настроен API-доступ к Меркурию и Честному Знаку. Данные из 1С выгружаются в Excel.
- **Что болит:** Российские LLM отстают в понимании отраслевой специфики. DeepSeek требует VPN или платного API. Конфиденциальность: технолог может скормить рецептуру в публичный сервис.
- **Что делать:** Выбрать 1 LLM-провайдера с закрытым контуром (корпоративный API YandexGPT или self-hosted). Настроить политику: что можно отправлять в ИИ, что нельзя.

## Стадия 3: Локальные внедрения

### Компания в целом
Запущены 3-4 пилота с измеримым эффектом. Выделен бюджет. ИИ встроен в отдельные переделы. Появились первые конфликты: технология меняется быстрее, чем процессы.

### Бизнес-модель — пилоты первого приоритета

**Пилот 1: Интеллектуальный расчёт норм закладки**
- **Что делает:** ИИ-модель на основе данных входного контроля (жирность, влажность, температура сырья) рассчитывает оптимальную рецептуру на партию. Вместо фиксированных нормативов — адаптивные.
- **Что болит:** Дорогое сырьё. Потери при обвалке и жиловке. Перерасход на 2-3% = миллионы рублей в месяц.
- **Что делать:** Собрать данные за 3-6 месяцев (входной контроль + фактический выход). Обучить модель на Python/scikit-learn. Интегрировать вывод в рабочее место технолога. KPI: +1.5-3% к выходу годного.
- **Российская специфика:** Качество сырья нестабильно. Модель должна учитывать поставщика, сезон, регион. Без этих признаков — не работает.

**Пилот 2: Видеоаналитика в цехе (безопасность + производительность)**
- **Что делает:** Камеры + CV-модель: контроль санитарной одежды, зонирования, перемещений. Отсутствие посторонних в чистых зонах. Скорость конвейера vs норматив.
- **Что болит:** Нарушения санрежима = риск закрытия партии. Ручной контроль не масштабируется.
- **Что делать:** Установить камеры в точках перехода между зонами. Обучить модель на своих данных (униформа, шапочки, фартуки). Интегрировать с СКУД.
- **Российская специфика:** Отечественные CV-решения (Ivideon, Macroscop) дешевле зарубежных, но требуют доработки под пищевку.

**Пилот 3: Предиктивная аналитика отказов холодильного оборудования**
- **Что делает:** Датчики температуры + модель прогноза: когда компрессор/испаритель выйдет из строя. Проактивное ТО вместо аварийного.
- **Что болит:** Отказ холода = порча сырья/продукции. Одна авария: минус миллионы рублей + простой цеха.
- **Что делать:** Установить датчики с Modbus-выходом на ключевые агрегаты. Модель прогноза на основе вибрации, температуры, наработки. Интеграция с графиком ТО.
- **Российская специфика:** Оборудование часто старше 10 лет, датчиков нет. Нужен минимальный набор: токовые клещи + датчик температуры + вибрации. Бюджет: ~50 тыс. руб. на единицу оборудования.

**Пилот 4: Авто-разметка и контроль маркировки**
- **Что делает:** CV-модель на конвейере: проверка нанесения этикетки, даты, кода Честного Знака. Автоматический отстрел брака.
- **Что болит:** Ошибка маркировки = штраф Роспотребнадзора + возврат партии из торговой сети. Ручной контроль — не 100%.
- **Что делать:** Камера над конвейером фасовки + OCR/проверка целостности этикетки. Пневмоотстрел бракованной упаковки.

### Управление
- **Что делает:** Куратор ИИ (главный технолог) ведёт портфель пилотов. IT обеспечивает интеграцию. Директор ежемесячно смотрит метрики.
- **Что болит:** У куратора нет бюджета и полномочий менять процессы. Начальники цехов видят в ИИ угрозу: зачем мне модель, если я и так знаю нормы выхода? Конфликт зон ответственности.
- **Что делать:** Создать кросс-функциональный комитет под председательством директора: технолог + IT + финансист + начальник цеха. Ежемесячный обзор пилотов. Мандат куратора: приоритетный доступ к данным всех подразделений.
- **Российская специфика:** Методологии ИИ-трансформации для средних производственных предприятий практически нет. Придётся адаптировать ITIL/Agile своими силами или с привлечением интегратора.

### Люди
- **Что делает:** Начата подготовка «операторов ИИ» на ключевых участках. Технологи проходят обучение работе с дашбордами.
- **Что болит:** Тревожность нарастает: «за нами следят», «нас заменят». Мастер цеха видит цифру выхода на экране — и понимает, что теперь его результат прозрачен для директора в реальном времени.
- **Что делать:** Коммуникация: это не замена, а помощь. Оператору — подсказка по режиму, а не контроль. Мастеру — инструмент для обоснования премии, а не кнут. ИИ-метрики в систему оценки: премия за работу с системой, а не наказание за отклонения.
- **Российская специфика:** Уровень цифровой грамотности на производстве низкий. Интерфейс — кнопочный, а не экранный. Дашборд = крупные цифры на простом фоне, не Grafana с 30 графиками.

### Технологии
- **Что делает:** Сбор данных с оборудования (Modbus/OPC-UA → сервер). LLM для работы с рецептурами и документацией (RAG). Видеоаналитика на отдельном сервере.
- **Что болит:** «Зоопарк»: камеры от одного вендора, датчики от другого, LLM от третьего. Данные не связаны. Нет единой платформы.
- **Что делать:** Определить интеграционную шину (Kafka или MQTT). Данные → единое озеро (ClickHouse или TimescaleDB). Отдельный сервер/виртуалка под ИИ-сервисы (камеры + LLM + модели). НЕ строить монолит.
- **Российская специфика:** Импортозамещение: Apache Kafka → Аэрофлот или Red Panda. ClickHouse — российская разработка, с импортозамещением проблем нет. LLM — GigaChat API (Сбер) или YandexGPT.

## Стадия 4: ИИ в основе

### Компания в целом
Процессы перепроектированы под ИИ. Меняются роли: мастер цеха из контролёра превращается в оператора ИИ-системы. Технолог — в аналитика данных. Оргструктура адаптируется.

### Бизнес-модель
- **Что делает:** Сквозная ИИ-система управления производством. Планирование закупок сырья на основе прогноза спроса с учётом сезонности. Оптимизация раскроя полутуш под заказы клиентов (максимальный выход дорогих отрубов). Динамическое ценообразование.
- **Что болит:** Волатильность цен на сырьё. Прогноз закупок ошибается — избыток или дефицит. Неоптимальный раскрой.
- **Что делать:** Интегрировать прогноз спроса (ML) + оптимизатор раскроя (LP/ILP) + динамическое ценообразование в единый контур. Планирование не на неделю вперёд, а на день.
- **Российская специфика:** Нестабильность поставок (санкции, логистика). Модель должна учитывать не только цену, но и надёжность поставщика, историю срывов.

### Управление
- **Что делает:** Куратор ИИ → начальник отдела цифровой трансформации. Прямое подчинение директору. Бюджет: 3-5% от выручки.
- **Что болит:** Двойное управление: старые процессы ещё работают, новые уже внедряются. Конфликт поколений: «старая гвардия» vs «цифровые».
- **Что делать:** Оргструктура: выделить ИИ-функцию в отдельное подразделение. Начальник ИИ-отдела наравне с главным технологом и начальником производства. Регулярный кросс-функциональный совет.
- **Российская специфика:** Найти начальника ИИ-отдела с опытом в пищевой переработке — почти невозможно. Растить своего или брать из смежной отрасли (фарма, агро).

### Люди
- **Что делает:** Новые роли: оператор ИИ-систем (на конвейере), аналитик качества (ОТК), ИИ-технолог (производство). Старые должностные инструкции списаны.
- **Что болит:** Радикальная смена ролей. Обвальщик, который 20 лет работал руками, теперь должен интерпретировать данные на экране. Часть людей не адаптируется.
- **Что делать:** Переподготовка с гарантией занятости. Программа: 3 месяца обучения → стажировка в новой роли → экзамен → новая должность. Кто не проходит — остаётся на вспомогательных операциях. Важно: без увольнений за некомпетентность в ИИ на этапе перехода.
- **Российская специфика:** Программ переподготовки для пищевой отрасли нет — придётся создавать с нуля или с привлечением регионального колледжа.

### Технологии
- **Что делает:** Единая цифровая платформа. Мониторинг в реальном времени: от приёмки сырья до отгрузки. Цифровой двойник производственной линии. Все ИИ-сервисы в одном контуре.
- **Что болит:** Интеграция с Меркурием и Честным Знаком. Отказоустойчивость: простой конвейера из-за сбоя ИИ недопустим.
- **Что делать:** Платформа на микросервисах. Каждый ИИ-сервис — отдельный контейнер. Брокер сообщений (Kafka) — единая шина. Данные хранятся локально (не в облаке). Автономный режим: если ИИ недоступен, линии работают по базовым алгоритмам.
- **Российская специфика:** Полный контур на российском ПО: Astra Linux + СУБД Arenadata/ClickHouse + Kafka (Red Panda) + MLflow для управления моделями. Сертификация ПО для интеграции с госсистемами.

## Стадия 5: Бизнес на ИИ

### Компания в целом
ИИ — основа конкурентоспособности. Сквозная прослеживаемость от поля до полки (блокчейн-подтверждение для ритейла). Гибридная организация: люди + ИИ-агенты + роботизированные линии.

### Бизнес-модель
- **Что делает:** Прогноз спроса на уровне SKU × день. Автоматическое планирование закупок с учётом прогноза цен на сырьё. Оптимальный раскрой под каждый заказ. ИИ-агенты управляют цепочкой поставок.
- **Что болит:** Высокая сложность, зависимость от данных, киберриски.
- **Что делать:** ИИ-агент по закупкам (анализ рынка + тендеры). ИИ-агент по качеству (авто-анализ лабораторных данных + предиктивные предупреждения). ИИ-агент по продажам (персонализация под ритейл-сети).
- **Российская специфика:** Премьер-министр подписал план внедрения «Индустрии 4.0» в пищевой отрасли до 2030 года. Возможны субсидии и налоговые льготы.

### Управление
- **Что делает:** ИИ-функция растворена: каждое подразделение имеет ИИ-компетенцию. Стратегический ИИ-совет при директоре. M&A в сфере AgTech и FoodTech.
- **Что болит:** Удержание ИИ-специалистов на заводе в регионе. Конкуренция за кадры с IT-сектором и финтехом.
- **Что делать:** Удалённые ИИ-специалисты + гибридный офис. Партнёрство с региональным вузом: базовая кафедра, целевой набор. Опционы/доля в прибыли для ключевых ИИ-специалистов.
- **Российская специфика:** Релокация специалистов в регионы через программы Минсельхоза. Льготная ипотека для аграриев и переработчиков.

### Люди
- **Что делает:** Гибридная рабочая сила: люди + ИИ-агенты. У каждого производственного менеджера — ИИ-ассистент. У каждой линии — цифровой двойник. Кадровая служба управляет не только людьми, но и ИИ-ресурсами.
- **Что болит:** Новая реальность: начальник цеха управляет не 20 людьми, а 15 людьми + 3 ИИ-агентами + 2 роботизированными линиями. Нужны новые компетенции.
- **Что делать:** Внутренний ИИ-университет. Система наставничества: ИИ-специалист + технолог в паре. Ротация: каждый сотрудник раз в год проходит стажировку в ИИ-отделе.

### Технологии
- **Что делает:** Полностью российский стек. Цифровой двойник завода. ИИ-агенты для каждой функции. Блокчейн-прослеживаемость для ритейла. Автономные линии фасовки и упаковки.
- **Что болит:** Санкционные риски. Зависимость от единственного поставщика ПО. Кибербезопасность.
- **Что делать:** Multi-vendor стратегия: минимум 2 поставщика на каждый критический компонент. Резервный контур на случай отключения от интернета. Пентесты и аудит безопасности ежеквартально.
- **Российская специфика:** Сертификация КИИ (критической информационной инфраструктуры) обязательна для пищевых производств с 2025 года. Требования ФСТЭК должны быть учтены на стадии проектирования.

## Антипаттерны (чего не делать)

- Начинать с «внедрения ИИ» без привязки к конкретному процессу и метрике
- Доверять ChatGPT рецептуры без верификации технологом
- Ставить камеры без уведомления сотрудников и без объяснения целей
- Внедрять ИИ-отчётность для директора, не дав инструментов мастерам цеха
- Запускать пилот без measurement baseline (как измерим, что стало лучше?)
- Игнорировать нестабильность API госсистем (нужен офлайн-режим)
- Экономить на датчиках — модель без данных бесполезна
- Пытаться автоматизировать хаос: сначала навести порядок в данных, потом ИИ
